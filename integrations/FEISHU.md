# 飞书自建应用本机接入（0.1.0 beta）

目标：用户自己运行媒体处理；飞书单聊机器人收链接、返回确认与最终飞书文档。不需要我们的公网转录服务器。此版本不是跨企业商店应用，不支持多人共用私有数据。

1. 在飞书开放平台创建企业自建应用，添加机器人能力。后台配置同一个App ID/App Secret；不要把Secret提交仓库。
2. 开通单聊消息接收/以机器人发送消息、云文档创建/编辑/读回、素材上传等对应权限，发布应用并让目标账号可见；具体权限名称以当前控制台为准。
3. 订阅 im.message.receive_v1（接收消息v2.0），选择长连接。自建应用长连接需要本机能访问飞书，商店应用需另按其支持模式配置。
4. 本机后台先测试Agent和飞书文档/图片配置。首次可用普通网站设置配置，停止网站后换桥接启动，避免同目录多个后端进程。
5. 安装 `pip install -r integrations/requirements-feishu.txt`；设置环境 `FEISHU_ALLOWED_OPEN_IDS=ou_你的真实open_id`，只允许一个明确账号。无需在聊天中贴Secret。
6. 从项目目录执行 `python3 -m integrations.feishu_bot`。它同时运行本机API和飞书长连接；不要再对相同STATE启动第二个uvicorn。
7. 白名单用户单聊发B站/YouTube单视频链接。收到确认后，本机执行、自动保存当前配置飞书空间，结束再回复文档链接。RSS暂用网页选单集。

只支持文本单聊；群聊和非白名单用户不处理。事件ID落盘去重，确认和结果使用回复UUID减少重复。下载/转录不是飞书代执行。电脑休眠或退出时不能保证消息送达或即时处理；本版不是持久消息队列/断点恢复方案。只配置App凭据不等于用户OAuth；这版输出在自建应用配置的文档空间，不是任意用户自动授权个人Wiki。

代码和SDK handler已测试，未用真实账号进行长连接收消息→回复端到端验收。实时连接状态可在飞书事件日志检查。需要应用已发布、真实open_id、可访问目标文档；真实联调应由目标用户发送测试链接。
